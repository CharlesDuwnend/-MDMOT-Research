## 三轮，每轮三项

完整机器可读证据见 `SHORT_V2_INDEPENDENT_AUDIT.json`。其中 2 项合同通过，7 项
存在缺陷或证据范围不足；“完成审计”不等于“方法通过”。

| 轮次 | 检查 | 实证与判断 |
|---|---|---|
| R1.1 | 数据与标签 | 15/5 分组互斥且属于 train；独立解析原始 XML 核对 200 个真实检测，标签差异 0。 |
| R1.2 | teacher 构建 | 说明写 8 帧 trimmed mean，代码实际取最早 8 条检测并算普通均值。反例中 8 条全来自同一帧；严格 future 过滤保留，但聚合合同不一致。 |
| R1.3 | checkpoint 与硬件 | checkpoint 完整；CUDA 实际名称为 DGX Display，旧快照唯一对应物理 GPU2/4096 MiB。UUID 字段只抄自环境变量，不是实际 CUDA UUID。 |
| R2.1 | 实际算子 | CPU 合同测的是另一个模型。生产模型的 dustbin 使用 valid_count/padded_width，单纯增加 padding 即改变输出 0.013408；真 K=0 输出不有限。候选置换测试通过。 |
| R2.2 | 训练损失 | METHOD_SPEC 中的 hard-negative margin 没有实现。BCE 反例中错误 Top-1 的损失 0.080679，小于正确 Top-1 的 0.644397，下降的 BCE 不能替代排序证据。 |

| R3.1 | scorer | 无正候选事件不进入 R@1/MRR 分母，dustbin 不参与排序。构造始终输出极大 no-match logit 的模型，仍可得到条件 R@1=1。旧 calibration 的 no-match 读数全为 null。 |
| R3.2 | 独立重放 | 真实 128 事件中的 122 个有正候选，独立 R@1/MRR 与生产 scorer 一致；记录的五对宏平均复算一致。不能外推为完整数据重放。 |
| R3.3 | 方法与主基线 | 当前输入是旧缓存的 256-D 池化向量，未训练 backbone/空间图、未接 P26。只能算向量排序探针；作为最终模块会触及原 METHOD_SPEC 自己规定的 post-pooling ranker 停止边界。 |

R3.1 是评估覆盖不完整，不代表已报告的条件排名数字算错。R1.3 是真实硬件约束违反，
不能单凭硬件误选推断数值无效。缺失损失、不同的合同模型、teacher 聚合差异等才是
这次运行不足以验证声明方法的具体原因。

P54 的 30,000 fit events 来自每对按时间顺序取最早 2,000 个事件，1,200 次更新为
有放回抽样；不能称为完整序列覆盖或若干有效全数据 epoch。不得直接沿用 P53 的
55,236 步当作 P54 全量 schedule，因为两者的数据单元和 batch 定义不同。

## 本阶段完成的修复

新增 `scripts/verified_gpu.py`：先根据 nvidia-smi 拒绝物理 GPU2 和所有不超过
4GB 的卡，再按完整 UUID 设置可见设备，最后在实际进程中同时比对 CUDA driver
UUID、PyTorch 型号及总显存。可在核验后同进程执行训练脚本，避免把独立探针的
正确设备误当成训练进程的设备。

真实 GPU3 核验为 A100-SXM4-40GB，driver UUID 与请求一致；9 项硬件约束回归测试
通过。P26 封存清单的 658 个文件全部通过 SHA-256 校验。证据见
`GPU_GUARD_AND_P26_RECEIPT.json`。本阶段没有启动模型训练，没有使用物理 GPU2，
没有读取原始 official-val/test 数据，没有删除数据或 checkpoint。

旧训练代码、旧收据、旧 checkpoint 不覆盖；由本审计解释和限制其有效性。
本次审计脚本在结果导出时先后出现 relative-path 和 NumPy-array JSON 序列化错误，
已修复并完成最终整轮执行；两次失败均未写出 PASS 报告，也未影响旧实验文件。

## 下一步应解决什么

继续研究前先解决“学生到底被迫学到什么”：GT 选出的同 source-view 未来原型很容易
匹配同 source-view 当前候选，这与从 target 学到跨视角身份线索不是同一证据。不能
仅加训练步数、调损失权重或把当前 ranker 改名继续。

下一次可训练方案需要形成以下可复核合同，再决定是否训练：

1. 明确表示在 P26 哪个真实特征/身份分支发生改变，列出该分支的空间或时序输入；
   旧 256-D 向量探针的读数只能作为诊断。
2. 学习目标必须通过 target 交换、候选复制、同 source-view 自蒸馏和无 teacher
   控制，证明损失依赖可推理的跨视角身份信息。零损失复制反例必须被消除或明确
   归为无增益控制，不能只通过置换不变测试。
3. 若保留 future teacher，先规定逐帧去重、trim 比例、缺失 donor 处理和时间覆盖；
   然后用 train-only 数据确认可观察性。明确正候选条件排序与全事件/no-match 两套分母。
4. 独立筛查完整链条的同任务先例及相邻方法，并补齐预注册中的算子、损失、真实
   生产模型测试和对照。跨领域蒸馏先例本身不是本次 STOP 的理由。
5. full schedule 必须从新的事件/分组总数和 batch 采样定义计算。按 UUID 启动并
   保存实际硬件证据；先过新的 train-only 门，再讨论 P26 隔离接入及正式评估。

这是一份尚待研究的设计任务书，不是已经选出、验证或获准训练的新方法。
