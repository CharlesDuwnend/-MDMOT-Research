# P62 novelty screen

No novelty or firstness claim is made. The narrow proposed boundary is a learned
prefix-causal **owner-state transition** with explicit provisional/final semantics.

| Prior / local result | Collision risk | P62 boundary |
|---|---|---|
| ReST, LMGP, MCTR, FusionTrack, graph/network-flow MOT solvers | direct graph association and global state optimization | P62 must show state contamination and bounded replay, not a graph reranker |
| fixed-lag/prefix mean in this workspace | direct local collision; it changed scores but not state | P62 must mutate provisional owner state and test descendant decisions |
| Tracklet quality/uncertainty gates | quality-gate collision | P62 output is a state transition and partition, not a threshold or confidence gate |
| SuperGlue/OT and P60 | assignment/operator collision | P62 does not use transport or differentiable assignment |
| owner-state synthetic contract | mechanism prerequisite only | real train-pair prefix evidence and descendant replay are required |

The direct same-task boundary is high risk. The candidate is kept only if its data
contract proves legal prefix observability, the CPU state transition is causal, and
held-out pair replay changes descendant owner state rather than only final IDs. A
failed state-contamination or delayed-control check is a STOP.
